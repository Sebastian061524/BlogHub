# BlogHub 接口设计（Day 1 草案）

> 已整理本周 MVP 的 10 个接口，覆盖注册登录、文章 CRUD、分类列表和评论发布／查询。
> 本文是接口契约，不代表接口已经实现或通过测试。

## 1. 通用约定

- 本地服务地址由工程启动配置决定；本文路径均为相对于服务地址的路径。
- 请求体和响应体使用 JSON；有请求体时，请求头使用 `Content-Type: application/json`。
- 字段使用小写字母加下划线命名，例如 `category_id`、`article_id`。
- 页码和资源标识使用 32 位正整数，允许范围为 1–2147483647；超出范围按参数错误处理。
- 受保护接口通过请求头 `Authorization: Bearer <token>` 携带登录获得的 JWT；`<token>` 为占位符，不是实际令牌。
- 服务端验证凭证后确定当前用户，不使用请求体中的用户标识代替登录身份。
- 注册和登录无需 JWT；JWT 有效期暂定为 2 小时（7200 秒），到期后需重新登录，本周不提供自动续期或刷新令牌接口。
- 文章列表、详情、分类列表和评论列表为公开查询，不要求 Authorization 请求头；没有请求体，不要求 Content-Type 请求头。
- 时间字段暂定使用带时区偏移的 ISO 8601 字符串，精确到秒，例如 `2026-11-02T16:00:00+08:00`。本项目暂定按 Asia/Shanghai 时区写入和读取数据库时间，再按此格式返回；不能把其他时区的时间直接标为 +08:00。

统一响应字段约定：

| 字段 | JSON 类型 | 含义 |
| --- | --- | --- |
| status | integer | 业务成功标识：1 表示成功，0 表示失败 |
| message | string | 结果说明，不包含内部堆栈、SQL 或敏感信息 |
| data | object 或 null | 成功时的业务数据；没有数据或失败时为 null |

HTTP 状态码表示 HTTP 层面的结果，响应体中的 `status` 是本项目定义的业务标识。例如，发布成功的 HTTP 状态码是 201，响应体的 status 是 1，两者不能混为一谈。

接口清单：

| 用途 | 方法 | 路径 | 访问要求 | 成功状态码 |
| --- | --- | --- | --- | --- |
| 注册用户 | POST | /users | 公开 | 201 |
| 登录 | POST | /auth/login | 公开 | 200 |
| 发布文章 | POST | /articles | 已登录 | 201 |
| 文章列表 | GET | /articles | 公开 | 200 |
| 文章详情 | GET | /articles/{article_id} | 公开 | 200 |
| 修改文章 | PUT | /articles/{article_id} | 已登录且为作者 | 200 |
| 删除文章 | DELETE | /articles/{article_id} | 已登录且为作者 | 200 |
| 分类列表 | GET | /categories | 公开 | 200 |
| 发布评论 | POST | /articles/{article_id}/comments | 已登录 | 201 |
| 评论列表 | GET | /articles/{article_id}/comments | 公开 | 200 |

## 2. 注册用户

### 2.1 基本信息

| 项目 | 约定 |
| --- | --- |
| 用途 | 创建一个新用户账号 |
| HTTP 方法 | POST |
| 路径 | /users |
| 是否需要登录 | 否，不要求 Authorization 请求头 |
| 请求格式 | Content-Type: application/json |
| 成功 HTTP 状态码 | 201 Created |

注册成功后不自动登录，不返回登录凭证；用户需要再调用登录接口获取凭证。

### 2.2 请求参数

本接口没有路径参数或查询参数，以下字段放在 JSON 请求体中。

| 字段 | JSON 类型 | 是否必填 | 校验规则 |
| --- | --- | --- | --- |
| user_name | string | 是 | 去除首尾空白后为 3–20 个字符，不允许内部空白，区分大小写且不能重复 |
| password | string | 是 | 6–64 个字符，仅允许英文字母、数字和英文半角标点（ASCII U+0021–U+007E），不允许任何空白，不强制混合字符类型 |

补充规则：

- 字段缺失、为 null、类型不符或为空字符串时返回参数错误。
- 用户名先去除首尾空白，再检查长度、内部空白和唯一性，并保存处理后的用户名。
- Alice 与 alice 是不同用户名，可分别注册；Alice 与首尾带空白的同名输入则视为重复。
- 密码出现非法字符时直接拒绝，不自动去除空格、替换字符或改变大小写。
- 本接口只接受 user_name 和 password；提交 id、password_hash 等未定义字段时返回参数错误。
- 密码哈希由服务端完成，不要求调用方提交哈希结果；响应及日志不得包含原始密码或密码摘要。

### 2.3 请求示例

请求方法与路径：`POST /users`

请求头：`Content-Type: application/json`

请求体（以下为测试示例，不是真实账号凭据）：

```json
{
  "user_name": "Alice",
  "password": "BlogHub!2026"
}
```

### 2.4 业务处理约定

1. 校验请求体及字段类型，处理用户名首尾空白，并按规则校验用户名和密码。
2. 按区分大小写的规则检查用户名是否重复。
3. 服务端进行密码哈希，保存新账号；用户标识由数据库生成。
4. 账号保存成功后返回注册成功，不创建登录凭证。

数据库唯一约束是用户名不重复的最终保障。即使事先查重通过，写入时仍可能遇到重复用户名，此类冲突同样返回 409，不作为普通系统错误处理。

### 2.5 成功响应

HTTP 状态码：`201 Created`

```json
{
  "status": 1,
  "message": "注册成功",
  "data": null
}
```

data 为 null 表示不返回用户业务数据，不表示整个响应体为空；不返回用户标识、密码、密码摘要或登录令牌。

### 2.6 失败情况

| 场景 | HTTP 状态码 | message 示例 | 结果 |
| --- | --- | --- | --- |
| JSON 格式错误、字段缺失、类型错误或未定义字段 | 400 Bad Request | 请求参数不合法 | 不创建账号 |
| 用户名处理后长度不符或仍有内部空白 | 400 Bad Request | 用户名须为 3–20 个字符且不能包含内部空白 | 不创建账号 |
| 密码长度不符、包含空白或允许范围外字符 | 400 Bad Request | 密码须为 6–64 个字符，仅允许英文字母、数字和英文半角标点 | 不创建账号 |
| 用户名格式合法但已经存在 | 409 Conflict | 用户名已被注册 | 不新增账号，不改变已有账号 |
| 系统内部错误 | 500 Internal Server Error | 系统繁忙，请稍后重试 | 写入失败时回滚，不返回内部错误细节 |

参数错误示例，HTTP 状态码为 400：

```json
{
  "status": 0,
  "message": "用户名须为 3–20 个字符且不能包含内部空白",
  "data": null
}
```

用户名冲突示例，HTTP 状态码为 409：

```json
{
  "status": 0,
  "message": "用户名已被注册",
  "data": null
}
```

先完成输入校验，再判断用户名冲突；同时存在多项参数错误时可返回其中一项明确提示。不需要登录即可调用注册接口，未携带登录凭证不属于注册失败原因。

### 2.7 后续接口测试清单

- [ ] 未登录且输入合法：返回 201、status 为 1、data 为 null，账号可以用于后续登录。
- [ ] 同名重复注册：返回 409，不新增账号、不覆盖已有账号。
- [ ] Alice 与 alice 可分别注册；首尾带空白的 Alice 与已有 Alice 冲突。
- [ ] 用户名去除首尾空白后长度恰好为 3 或 20 个字符：允许；不足 3、超过 20 或包含内部空白：返回 400。
- [ ] 合法密码长度恰好为 6 或 64 个字符：允许；长度不足 6 或超过 64：返回 400。
- [ ] 密码包含空格、制表符、换行、中文或全角标点：返回 400，不删除非法字符后继续注册。
- [ ] 请求体缺少字段、字段为 null、类型不符、为空字符串或含未定义字段：返回 400。
- [ ] 存储的是密码哈希，响应及日志均不泄露密码、密码摘要或登录令牌。
- [ ] 注册成功不自动登录；并发同名注册最多创建一个账号，重复写入返回 409。

以上为待执行的验收场景，须在实际实现并测试后勾选。

## 3. 发布文章

### 3.1 基本信息

| 项目 | 约定 |
| --- | --- |
| 用途 | 创建一篇公开文章 |
| HTTP 方法 | POST |
| 路径 | /articles |
| 是否需要登录 | 是 |
| 权限 | 任意已通过身份认证的用户均可发布 |
| 成功 HTTP 状态码 | 201 Created |

路径表示文章集合，POST 表示向集合中创建文章。当前没有草稿流程，创建成功即公开发布。

### 3.2 请求头

| 名称 | 是否必填 | 内容 |
| --- | --- | --- |
| Authorization | 是 | Bearer <token> |
| Content-Type | 是 | application/json |

### 3.3 请求参数

本接口没有路径参数或查询参数，以下参数全部放在 JSON 请求体中。

| 字段 | JSON 类型 | 是否必填 | 校验规则 |
| --- | --- | --- | --- |
| title | string | 是 | 1–50 个字符，不能全部为空白 |
| body | string | 是 | 1–1000 个字符，不能全部为空白 |
| category_id | integer | 是 | 必须为正整数，并且分类必须存在 |

补充规则：

- 字段缺失、为 null 或类型不符时，返回参数错误。
- 标题和正文不得为空字符串；可以包含正常空格，正文可以包含换行。
- 纯空白包括仅由空格、制表符、换行等空白字符构成的内容。
- 长度按字符数计算，不按存储字节数计算。
- 本接口只接受上表中的字段；提交 `user_id`、`id`、时间字段或其他未定义字段时返回参数错误，避免误认为这些字段可由调用方控制。

### 3.4 请求示例

请求方法与路径：`POST /articles`

请求头：

```http
Authorization: Bearer <token>
Content-Type: application/json
```

请求体：

```json
{
  "title": "我的第一篇博客",
  "body": "今天开始独立开发 BlogHub，记录自己的学习过程。",
  "category_id": 1
}
```

示例假设分类 1 已存在，并且请求携带有效登录凭证。

### 3.5 业务处理约定

1. 验证登录凭证；缺少、无效或过期时拒绝发布。
2. 校验请求体结构、字段类型、必填项和内容长度。
3. 检查分类是否存在。
4. 使用当前登录用户作为作者，创建文章；文章标识由数据库生成，发布时间和初始修改时间由服务端／数据库确定。
5. 创建成功后立即公开，返回新文章标识，供调用方后续查询详情。

任何校验或写入失败时均不得留下本次发布的文章记录。成功仅在数据已保存后返回，不能在写入前提前返回成功。

### 3.6 成功响应

HTTP 状态码：`201 Created`

```json
{
  "status": 1,
  "message": "文章发布成功",
  "data": {
    "article_id": 123
  }
}
```

| 字段 | 含义 |
| --- | --- |
| data.article_id | 新创建文章的唯一标识，示例值为 123 |

发布成功无需重复返回全文；文章详情由后续详情查询接口提供。响应不得包含密码、密码摘要或登录令牌。

### 3.7 失败情况

| 场景 | HTTP 状态码 | message 示例 | 结果 |
| --- | --- | --- | --- |
| JSON 格式错误、缺少字段、类型错误、未定义字段 | 400 Bad Request | 请求参数不合法 | 不创建文章 |
| 标题为空白或超过 50 个字符 | 400 Bad Request | 标题必须为 1–50 个字符且不能全部为空白 | 不创建文章 |
| 正文为空白或超过 1000 个字符 | 400 Bad Request | 正文必须为 1–1000 个字符且不能全部为空白 | 不创建文章 |
| category_id 不是正整数 | 400 Bad Request | 分类标识必须为正整数 | 不创建文章 |
| 缺少、无效或过期的登录凭证 | 401 Unauthorized | 请先登录或重新登录 | 不创建文章 |
| 分类标识合法，但对应分类不存在 | 404 Not Found | 分类不存在 | 不创建文章 |
| 系统内部错误 | 500 Internal Server Error | 系统繁忙，请稍后重试 | 写入失败时回滚，不返回内部错误细节 |

参数错误示例，HTTP 状态码为 400：

```json
{
  "status": 0,
  "message": "标题必须为 1–50 个字符且不能全部为空白",
  "data": null
}
```

未通过身份认证示例，HTTP 状态码为 401：

```json
{
  "status": 0,
  "message": "请先登录或重新登录",
  "data": null
}
```

分类不存在示例，HTTP 状态码为 404：

```json
{
  "status": 0,
  "message": "分类不存在",
  "data": null
}
```

当请求同时存在多项错误时，先进行身份认证；认证通过后再校验参数，参数合法后再检查分类是否存在。参数同时有多项错误时，可返回其中一项明确提示，不要求固定字段检查顺序。

说明：发布文章面向所有已登录用户，本接口没有“修改他人文章”的权限场景。403 Forbidden 将在修改、删除文章接口中用于表达已登录但无操作权限。

### 3.8 后续接口测试清单

- [ ] 有效登录凭证和合法输入：返回 201、status 为 1，并返回 article_id。
- [ ] 新文章可被查询，作者是当前登录用户，分类及内容正确。
- [ ] 未携带、无效或过期的凭证：返回 401，不新增文章。
- [ ] 字段缺失、null、类型错误、空字符串或纯空白：返回 400，不新增文章。
- [ ] 标题恰好 50 个字符、正文恰好 1000 个字符且其余条件合法：允许发布。
- [ ] 标题 51 个字符或正文 1001 个字符：返回 400，不新增文章。
- [ ] 分类标识为零、负数或非整数：返回 400。
- [ ] 分类标识合法但分类不存在：返回 404，不新增文章。
- [ ] 请求体额外包含 user_id 等未定义字段：返回 400，不能冒充其他作者。
- [ ] 响应及日志不暴露密码、密码摘要、登录令牌、堆栈或 SQL。

以上为待执行的验收场景，须在实际实现并测试后勾选。

## 4. 用户登录

### 4.1 基本信息

| 项目 | 约定 |
| --- | --- |
| 用途 | 验证已有账号的用户名和密码，获取登录凭证 |
| HTTP 方法 | POST |
| 路径 | /auth/login |
| 是否需要登录 | 否，不要求 Authorization 请求头 |
| 请求格式 | Content-Type: application/json |
| 成功 HTTP 状态码 | 200 OK |

登录不会创建新账号。登录接口不要求已有 JWT，也不能因为旧 JWT 已过期而阻止用户重新登录。

### 4.2 请求参数

本接口没有路径参数或查询参数，以下字段放在 JSON 请求体中，不放入 URL。

| 字段 | JSON 类型 | 是否必填 | 校验规则 |
| --- | --- | --- | --- |
| user_name | string | 是 | 去除首尾空白后为 3–20 个字符，不允许内部空白，查找账号时区分大小写 |
| password | string | 是 | 6–64 个字符，仅允许英文字母、数字和英文半角标点（ASCII U+0021–U+007E），不允许任何空白，不强制混合字符类型 |

补充规则：

- 字段缺失、为 null、类型不符或为空字符串时返回 400，不进入账号密码验证。
- 用户名处理规则与注册一致；密码不自动去除空格、替换字符或改变大小写。
- 本接口只接受 user_name 和 password；提交 user_id、password_hash、token 等未定义字段时返回参数错误。
- 请求中的 password 是用户输入的原始密码；由服务端根据已保存的密码哈希进行验证，不要求调用方提交密码哈希。

### 4.3 请求示例

请求方法与路径：`POST /auth/login`

请求头：`Content-Type: application/json`

请求体（以下为测试示例，不是真实账号凭据）：

```json
{
  "user_name": "Alice",
  "password": "BlogHub!2026"
}
```

示例假设用户 Alice 已注册，且密码与注册时一致。

### 4.4 业务处理约定

1. 校验请求体、字段类型、用户名和密码的输入规则。
2. 按处理后的用户名查询账号，区分大小写。
3. 验证密码；账号不存在或密码不匹配，均返回相同的 401 响应，不分别提示原因。
4. 验证成功后签发 JWT，凭证所代表的用户身份以服务端查到的账号为准。
5. 返回登录凭证及有效期，不返回密码或密码摘要。

输入校验失败和身份验证失败是不同情况：缺少 password 返回 400；用户名和密码格式合法，但账号不存在或密码错误，返回 401。

### 4.5 成功响应

HTTP 状态码：`200 OK`

```json
{
  "status": 1,
  "message": "登录成功",
  "data": {
    "token": "示例令牌",
    "expires_in": 7200
  }
}
```

| 字段 | JSON 类型 | 含义 |
| --- | --- | --- |
| data.token | string | 服务端签发的 JWT；示例令牌只是占位文本，实际调用必须使用真实签发的令牌 |
| data.expires_in | integer | 凭证自签发时起的有效时长，单位为秒，暂定 7200 秒，不是时间戳 |

调用受保护接口时，将 token 放入请求头：

```http
Authorization: Bearer <token>
```

user_id 不能替代 token 证明已登录，本次登录响应不额外返回用户信息。

### 4.6 失败情况

| 场景 | HTTP 状态码 | message 示例 | 结果 |
| --- | --- | --- | --- |
| JSON 格式错误、字段缺失、null、类型错误或未定义字段 | 400 Bad Request | 请求参数不合法 | 不签发令牌 |
| 用户名长度不符或包含内部空白 | 400 Bad Request | 用户名须为 3–20 个字符且不能包含内部空白 | 不签发令牌 |
| 密码长度不符或包含非法字符 | 400 Bad Request | 密码须为 6–64 个字符，仅允许英文字母、数字和英文半角标点 | 不签发令牌 |
| 输入格式合法，但用户名不存在或密码不匹配 | 401 Unauthorized | 用户名或密码错误 | 不签发令牌，不区分具体失败原因 |
| 系统内部错误 | 500 Internal Server Error | 系统繁忙，请稍后重试 | 不返回可用令牌或内部错误细节 |

参数错误示例，HTTP 状态码为 400：

```json
{
  "status": 0,
  "message": "请求参数不合法",
  "data": null
}
```

身份验证失败示例，HTTP 状态码为 401：

```json
{
  "status": 0,
  "message": "用户名或密码错误",
  "data": null
}
```

用户名不存在与密码错误使用相同的 HTTP 状态码、业务成功标识和提示，不返回“该用户不存在”等区分信息。

### 4.7 JWT 有效期与过期处理

- JWT 有效期暂定为 2 小时，响应中的 expires_in 与服务端实际签发的有效期保持一致。
- 服务端负责验证令牌的真实性和有效期，不信任调用方自行声明的用户身份或过期状态。
- 访问受保护接口时，凭证缺失、无效或过期均返回 401，不执行受保护操作。
- JWT 到期后，用户重新调用登录接口，用用户名和密码获取新令牌；本周不提供刷新令牌和自动续期功能。
- 调用方可根据 expires_in 提示重新登录，但客户端判断不能代替服务端验证。
- 原始密码、密码摘要、完整 JWT 及携带 JWT 的 Authorization 请求头均不得写入日志。

## 8. 删除文章

### 8.1 基本信息与参数

```json

  "data": null

```

### 8.3 权限、删除顺序与事务

1. 验证 JWT，校验文章标识。
2. 查询文章是否存在，比较登录用户 ID 与文章作者 ID；不存在返回 404，越权返回 403。
3. 在 Service 层的同一个数据库事务内，先删除该文章的全部评论，再删除文章。
4. 全部成功后提交；任一步失败，回滚整个删除操作，不得留下部分删除结果。

- 没有评论时，删除评论影响 0 行属于正常情况，应继续删除文章。
- 应确认目标文章确实删除；若执行时目标已不存在，返回 404，并回滚本次事务中的其他删除。
- 删除后文章详情和评论查询均返回 404，不能再对该文章发表评论；再次删除也返回 404。

### 8.4 失败情况

| 场景 | HTTP 状态码 | message 示例 |

| 当前用户不是文章作者 | 403 | 无权删除该文章 |
| 文章不存在或已删除 | 404 | 文章不存在 |
| 数据库删除等内部处理失败 | 500 | 系统繁忙，请稍后重试 |

- [ ] 作者删除没有评论的文章：同样返回 200。

data.items 为数组，每项包含整数 category_id 和字符串 name；没有分类时仍返回 200，data 为 `{"items": []}`，不得返回 null 或 404。该接口不返回分页字段。

系统内部错误返回 500，响应为 status 为 0、message 为通用错误提示、data 为 null。

### 9.3 后续接口测试清单

- [ ] 游客查询成功，返回全部预置分类的标识和名称，顺序符合约定。
- [ ] 没有分类数据时返回 200，items 为 []，不返回 404。
- [ ] 不提供分类新增、修改和删除接口。

## 10. 发布评论

### 10.1 基本信息与参数

| 项目 | 约定 |
| --- | --- |
| HTTP 方法与路径 | POST /articles/{article_id}/comments |
| 身份与权限 | 已登录用户可对存在的公开文章评论，无需是文章作者 |
| 路径参数 | article_id，必填，32 位正整数 |
| 查询参数 | 无 |
| 请求格式 | Content-Type: application/json |
| 成功状态码 | 201 Created |

| 请求体字段 | JSON 类型 | 是否必填 | 校验规则 |
| --- | --- | --- | --- |
| text | string | 是 | 1–500 个字符，不能全部为空白 |

- 缺少 text、null、类型错误、空字符串、纯空白或超过长度上限时返回 400；正常空格和换行允许保留。
- 请求体只接受 text；文章标识来自路径，评论者标识来自验证通过的 JWT，不接受请求体中的 article_id、user_id 等未定义字段。
- 目标文章必须存在且未删除。评论标识由数据库生成，发布时间由服务端／数据库确定。

### 10.2 请求与成功响应

```http
POST /articles/123/comments
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "text": "这篇学习记录很清楚。"
}
```

成功返回 HTTP 201：

```json
{
  "status": 1,
  "message": "评论发布成功",
  "data": {
    "comment_id": 456
  }
}
```

data.comment_id 为新评论的整数标识。成功响应不返回密码、密码摘要或登录令牌。

### 10.3 失败情况与处理顺序

先验证 JWT，再校验路径和请求体，最后检查目标文章并保存评论。失败时不得新增评论或留下指向不存在文章的评论。

| 场景 | HTTP 状态码 | message 示例 |
| --- | --- | --- |
| article_id 或请求体不合法 | 400 | 请求参数不合法 |
| JWT 缺失、无效或过期 | 401 | 请先登录或重新登录 |
| 文章不存在或已删除 | 404 | 文章不存在 |
| 系统内部错误 | 500 | 系统繁忙，请稍后重试 |

失败响应为 status 为 0、message 为对应提示、data 为 null。当前没有文章私密或评论封禁规则，不设置“只有作者才能评论”的权限限制。

### 10.4 后续接口测试清单

- [ ] 已登录用户对已有文章发表评论：返回 201 和 comment_id；评论者为当前登录用户。
- [ ] 文章作者与其他已登录用户均可发表评论，游客返回 401。
- [ ] 内容缺失、null、类型错误、空字符串、纯空白或 501 个字符：返回 400，不新增评论。
- [ ] 内容为 1 或 500 个字符且其余条件合法：允许发布。
- [ ] 请求体提交 user_id 等未定义字段：返回 400，不能冒充其他评论者。
- [ ] 文章标识非法返回 400，文章不存在或已删除返回 404。
- [ ] 发布后能在该文章的评论列表中查询到正确内容、评论者和发布时间。
